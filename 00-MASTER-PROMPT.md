# Master Prompt (verbatim brief)

> Archived exactly as issued, so every downstream conclusion can be traced back to the question that was actually asked.

**THESIS**

Investigate whether there is a large, defensible opportunity in automatically identifying and recovering freight revenue that carriers, brokers, or logistics operators fail to bill or collect because detention, TONU, layover, accessorials, lumper fees, demurrage, shortages, damages, invoice mismatches, and evidence are fragmented.

Do not assume detention alone is the product.

**CORE HYPOTHESIS**

```
Rate confirmation + GPS/ELD + appointment + BOL/POD + email/text + invoice
  -> entitlement detection
  -> amount calculation
  -> evidence package
  -> invoice/claim
  -> collection tracking
```

**RESEARCH QUESTIONS**

1. How much detention/accessorial revenue is missed?
2. Which buyer feels it most: carrier, broker, 3PL, shipper?
3. What do modern TMS platforms already automate?
4. Which startups already automate detention/accessorial recovery?
5. Can ELD/GPS + documents determine entitlement reliably?
6. Are customer-specific rate rules too heterogeneous?
7. Is evidence sufficiency the real bottleneck?
8. Can V1 work without deep TMS integration?
9. Is percentage-of-recovery pricing viable?
10. Which adjacent freight leakage problem is larger than detention?

**INITIAL COMPANIES/SUBSTITUTES**

McLeod Software; MercuryGate; Trimble Transportation; Descartes; Samsara; Motive; project44; FourKites; Transporeon; Highway; Triumph/TriumphPay; OTR Solutions; Denim; Relay Payments; freight audit/payment vendors; detention/accessorial automation startups; TMS billing modules.

**CAPABILITY MATRIX**

Score: rate confirmation ingestion, rate-rule extraction, GPS/ELD timestamps, appointment ingestion, POD/BOL ingestion, detention, TONU, layover, lumper, demurrage, accessorial detection, evidence package, invoice creation, claim submission, collection tracking, dispute workflow, portal, TMS integration, ELD integration, email/SMS ingestion, accounting integration, recovered-revenue analytics, performance pricing, customer-specific rules, multi-carrier/multi-shipper support.

**WHITE-SPACE HYPOTHESES TO ATTACK**

- A. automated detention recovery
- B. all-accessorial revenue recovery
- C. broker margin leakage
- D. freight contract entitlement engine
- E. evidence-first automated billing
- F. carrier recovery without TMS replacement
- G. shipper-side dispute prevention

**ECONOMIC TEST**

Find evidence on detention frequency/cost, missed accessorial billing, admin labor, collection success, TMS costs, and revenue-share models. Build at least 3 ROI examples.

**SOLO-FOUNDER MVP TEST**

Can V1 work from uploaded rate confirmation + BOL/POD + exported GPS timestamps + supporting emails, calculate entitlement, and generate an invoice/evidence packet without a TMS/ELD integration? Define the narrowest sellable V1.

**GLOBAL RULES**

- This is research, not implementation.
- Use 10-15 competitor/substitute agents, 2-4 category managers, 1 synthesis manager, 1 red-team manager, 1 final-decision manager.
- Use current web research and prioritize official docs/API docs/product pages/case studies/pricing.
- A missing feature is NOT white space.
- A surviving opportunity must prove: significant recurring pain, measurable economic value, clear buyer, poor incumbent coverage, poor substitute-stack coverage, strong add/switch rationale, solo-founder MVP feasibility, defensibility, expansion potential.
- Assume the founder is initially solo. Penalize ideas requiring a large team, many deep integrations, multi-year procurement, huge proprietary datasets, or 24/7 staffing before first revenue.
- Prefer V1s that can start with file upload, email forward, CSV, or a lightweight API.
- Require a direct answer to: "Why would a company add this when it already has software, staff, and consultants?"
- Synthesis manager must generate at least 5 candidate wedges.
- Red team must try to kill every wedge using incumbents, substitute stacks, internal build, consultants, pricing, switching cost, legal risk, and distribution.
- Final verdict must be exactly GO, PIVOT, or KILL.
- Do not code unless the final verdict is GO and the user later asks to build.

**FINAL OUTPUTS**

1. competitor landscape
2. capability matrix
3. substitute-stack matrix
4. buyer/JTBD matrix
5. top 5 wedges
6. red-team report
7. solo-founder MVP definition
8. pricing hypothesis
9. first-20-customer acquisition plan
10. GO/PIVOT/KILL memo
