# Method

## Structure

```
15 competitor / substitute agents   (parallel, independent web research)
        |
        v
 4 category managers                (synthesise + fill economic and buyer gaps)
        |
        v
 1 synthesis manager                (>= 5 candidate wedges)
        |
        v
 1 red-team manager                 (attempt to kill every wedge)
        |
        v
 1 final-decision manager           (GO / PIVOT / KILL)
```

## Rules applied throughout

- A missing feature is **not** white space. Absence of a capability only counts if paired with
  evidence of recurring, paid-for pain.
- Every material claim carries a URL. Unverifiable claims are labelled `UNVERIFIED` rather than
  smoothed over.
- The founder is assumed **solo**. Ideas requiring a large team, many deep integrations, multi-year
  procurement, huge proprietary datasets, or 24/7 staffing before first revenue are penalised.
- V1s that start with file upload, email forward, CSV, or a lightweight API are preferred.
- Every surviving wedge must answer directly: *"Why would a company add this when it already has
  software, staff, and consultants?"*

## Capability matrix scale

| Score | Meaning |
|---|---|
| 0 | Absent |
| 1 | Marginal / adjacent only |
| 2 | Partial, or requires heavy configuration, services, or a third party |
| 3 | Strong native capability, marketed and evidenced |

## Source hierarchy

1. Official product pages, developer/API docs, pricing pages
2. Published case studies, marketplace listings
3. SEC / investor material, industry association reports
4. G2 / Capterra / practitioner forums (used for pain evidence and verbatim quotes)
5. Press (lowest weight)

## Confidence labels

- **HIGH** — multiple primary sources agree, current (2024-2026)
- **MEDIUM** — single primary source, or secondary sources agreeing
- **LOW** — inferred, dated, or reported second-hand
- **UNVERIFIED** — could not be established; the source that would settle it is named
